# PassVault: mobile interaction and device-only mode

## Implemented

- **Mobile toolbar**: the redundant top hamburger is hidden; the bottom `Menu` dock remains. Search is an actual, always-visible input with a touch-friendly focus button; the theme switch is visible on mobile. Narrow-screen text buttons and basket controls wrap more safely.
- **Mobile baskets**: long-press an item icon/name or basket header (about 330 ms), drag toward the left/right carousel edge to auto-scroll across distant baskets, and release over the destination. No data is mutated until a valid drop. Standard swiping remains active until a long press. Desktop HTML drag/drop, explicit `Move` buttons, and keyboard basket order controls are retained.
- **Install app**: entry/sign-in, signed-in dashboard and Settings show install controls. Browser-native `beforeinstallprompt` is used where supported; iOS offers **Share → Add to Home Screen** instructions. Browser support and HTTPS hosting determine whether native install prompts appear.
- **Cloud sync switch**: dashboard, overview, and Settings → Encrypted backups allow pausing **vault uploads**. The preference is stored per signed-in account in this browser (a non-secret boolean). Existing cloud data is **not deleted**. Signing in, account features, and cloud-vault listing still use Supabase. An already-sent upload cannot be recalled; the code checks the preference again immediately before RPC after encryption to block uploads which have not started yet.
- **Device-only workflows**: after online account sign-in, choose `Work offline → Create new offline vault` or `Import encrypted offline vault`. The account dashboard also offers `Work offline: Create or import`. Offline vaults use the existing creation/unlock flows and open the normal interface. New or imported device-only vaults use reserved `device-` identifiers, never reuse cloud vault IDs/revisions, and cannot upload even if account cloud sync remains enabled. The user’s account-wide cloud-sync preference is **not changed** by entering device-only mode. The existing Argon2id / AES-GCM encrypted format remains unchanged. URL safety validation still applies to imported credentials. Device-only mode does not imply the vault is automatically persisted as a new file: **after every edit, download the encrypted backup**. This application still requires a network connection to open a deployed installation because it is an online-only PWA without a service worker; the existing PWA protection may lock even device-only vaults if the network disconnects. This is device-only storage, not guaranteed disconnected operation.
- **Safe lock / recovery**: when a modified device-only vault is manually locked, a best-effort encrypted-only local recovery is created using the existing key and recovery code. The recovery record is explicitly marked device-only and cannot be silently promoted to cloud storage. Local storage can fail or be erased; an explicit downloaded backup remains essential. Browser close/unload cannot reliably finish asynchronous encryption.
- **Export usability**: the standard encrypted backup export also exposes a persistent link in the current unlocked overview and backups settings, which can be tapped if iOS does not start the automatic download. Blob links are revoked and removed on lock.
- **Unlock UI**: the signed-in modal chooser now distinguishes existing cloud vaults from the device-only create/import path, with a mobile-accessible file picker. The existing encryption and KDF parameters are unchanged.
- **Sign-out safety**: when there are unuploaded edits, manual sign-out opens a backup checkpoint dialog. Preparing a backup exposes an explicit download link; the user must confirm they saved and verified it before signing out. Browsers cannot verify a completed download. The 15-minute security timeout still locks automatically, saving a best-effort encrypted local recovery instead of waiting for confirmation.

## Before real use

1. **Back up and test with a disposable vault** on desktop Chrome, Android Chrome, and iPhone Safari, including very small displays, rotation, drag-to-far-edge, file import, failed decrypt, auto-lock, resume after app switch, and download/reimport.
2. Run `npm ci`, `npm run build`, `npm run verify`, `npm run test:device-only`, `npm run test:offline-flow` and the existing regression suite **from a network-capable build environment**. The supplied source ZIP does not include installed dependencies or generated `dist`.
3. Have the sync-mode and lock/recovery modifications independently reviewed before storing real secrets. Existing encrypted cloud records and key derivation format were intentionally not modified.

## Known limitations

- This is **not an independently audited security release**; automated/static tests alone cannot establish security.
- A device-only new or imported vault is not continuously autosaved as a downloadable file. Its changes are in active memory (or a best-effort encrypted recovery on secure lock) until you export. If the browser or device crashes, new edits can be lost.
- The app is installable but **not launchable fully offline** in the current online-only architecture. Real offline app startup would require a separately reviewed offline asset/cache, auth, and local encrypted storage design.
- The UI cannot cancel a network request once transmitted. Disabling sync prevents future requests but cannot undo an upload already in flight or delete older cloud data.
